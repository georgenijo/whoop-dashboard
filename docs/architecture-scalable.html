Phase C — per-user Whoop OAuth

~3–5 days

  • Refactor daily_sync.py → iterate SELECT * FROM integrations WHERE provider='whoop'
  • Per-user token refresh + retry/backoff (failure on user A doesn't break sync for user B)
  • Stamp user_id on every recovery/cycle/sleep/workout insert

Phase D — data isolation audit

~2–3 days
  • Build forUser(uid).query(...) wrapper that auto-injects WHERE user_id = ?
  • Migrate every safeQuery call to the wrapper
  • Test that asserts no SELECT * on domain tables escapes the wrapper (regex or AST scan in CI)
  • Coach tools (query_recovery, etc.) take userId from request context, not env

Open decisions before kickoff

1. Hosted or self-host packaged?

Self-host: ship Docker compose + each user provides own Whoop developer credentials → sidesteps shared rate-limit pool → infra burden lives with users. Hosted: you absorb Whoop client quota → ~100 active users before throttling matters → you carry uptime/backup ops → low ops cost while small.

2. Apple-only or Apple + Google?

Apple-only: reuses existing iOS auth, smallest surface. Friction for Android-first users without Apple ID. Apple + Google: covers both ecosystems, ~1 day of extra work to wire Google Sign In, doubles auth-provider edge cases.

3. Encryption strategy for tokens at rest?

libsodium sealed box + single VAULT_KEY env: simplest, key rotation = re-encrypt all rows. Per-user derived key from Apple sub: compromise of DB alone leaks nothing without sub list — more complex, harder to migrate. SQLCipher whole-DB: opaque to inspection tooling, easiest to forget the key.

4. Sync trigger model?

Cron iterates all users: simple, predictable Whoop quota burn. On-demand only (UI button + Coach tool): zero idle quota cost, stale data unless user opens app. Hybrid: daily cron + on-demand for active users — likely best, slightly more code.

5. SQLite or Postgres at multi-tenant?

Stay SQLite: works to ~100 light users on the existing VM with WAL. Move to Postgres: opens path to read replicas, RLS, real connection pooling — pay the cost when you hit ~50 users actively syncing concurrently. Defer until pain.
