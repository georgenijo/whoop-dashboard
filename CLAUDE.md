# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A personal health analytics dashboard that pulls data from the Whoop wearable API and displays recovery, sleep, strain, and workout metrics. Built with Python, Streamlit, and Plotly. Includes a SQLite storage layer for historical data and an LLM-powered insights engine that generates daily health analysis.

## Commands

```bash
# Setup
cp .env.example .env          # then fill in WHOOP_CLIENT_ID and WHOOP_CLIENT_SECRET
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# Run the dashboard
streamlit run app.py           # serves on http://localhost:8501

# Run the sync + insights manually
python daily_sync.py           # fetches last 7 days, syncs to DB, generates LLM insight
```

No test suite, linter, or build step is configured.

## Architecture

### Module layout

- **`app.py`** — Single-file Streamlit app: auth flow, data fetching, DataFrame construction, KPI metrics, and all Plotly charts. Uses `@st.fragment` to isolate chart sections and `@st.cache_data(ttl=600)` for a 10-minute fetch cache. Also syncs fetched data to SQLite and displays the latest LLM insight.
- **`whoop/auth.py`** — OAuth2 flow against `api.prod.whoop.com`. Persists tokens to `tokens.json` (atomic write via tmp+rename). Thread-safe token refresh with `_refresh_lock`. Auto-refreshes tokens 60 seconds before expiry.
- **`whoop/client.py`** — `WhoopClient` REST client wrapping the `/developer/v2` API. Handles pagination (`_get_all` with `nextToken`), raises `AuthError` (401) and `RateLimitError` (429). `fetch_all_parallel()` hits all 6 endpoints concurrently via `ThreadPoolExecutor(max_workers=5)`.
- **`whoop/db.py`** — SQLite persistence layer. Tables for `recovery`, `cycles`, `sleep`, `workouts`, and `insights`. Each table stores parsed fields plus the raw JSON. Uses `INSERT OR REPLACE` for idempotent syncs. WAL journal mode for concurrent reads. DB file: `whoop_data.db` at project root (gitignored).
- **`whoop/insights.py`** — LLM insights engine. Builds a text summary from the last 30 days of DB data, sends it to Claude Sonnet via the `claude` CLI with a health-analyst system prompt, and stores the result in the `insights` table.
- **`daily_sync.py`** — Standalone sync script (runs outside Streamlit). Fetches the last 7 days from the Whoop API, syncs to SQLite, then generates a fresh LLM insight. Intended to run as a cron/systemd timer job.
- **`systemd/`** — Service and timer units: `whoop-sync.timer` triggers `daily_sync.py` at 7am daily; `whoop-dashboard.service` runs the Streamlit app; `whoop-tunnel.service` runs a Cloudflare tunnel for remote access.

### Data flow

1. OAuth callback → token stored in `st.session_state` + `tokens.json`
2. `fetch_all_parallel()` retrieves profile, body, cycles, recovery, sleep, workouts in parallel
3. Fetched data is synced to SQLite via `sync_all()` (both from the dashboard and from `daily_sync.py`)
4. `build_*_df()` functions filter to `SCORED` records, parse dates, convert units (ms→hours, kj→kcal), and produce pandas DataFrames
5. DataFrames drive KPI metrics (with day-over-day deltas) and Plotly charts
6. `generate_insight()` reads 30 days of history from the DB, sends it to Claude, and saves the analysis to the `insights` table

### Key conventions

- Only records with `score_state == "SCORED"` are processed; naps are excluded from sleep data
- Whoop API base: `https://api.prod.whoop.com/developer`
- Environment variables: `WHOOP_CLIENT_ID`, `WHOOP_CLIENT_SECRET`, `WHOOP_REDIRECT_URI` (defaults to `http://localhost:8501`)
- `tokens.json` at project root is the persistent token store (gitignored)
- `whoop_data.db` at project root is the SQLite database (gitignored)
- LLM insights are generated by shelling out to the `claude` CLI (requires Claude Code to be installed)

## Roadmap

The project is actively evolving beyond a stateless dashboard:

1. **Database layer** — Adding persistent storage so Whoop data is accumulated over time rather than fetched live each session
2. **LLM insights layer** — Adding an AI/cloud layer that analyzes stored data to surface patterns, trends, and natural-language health insights
